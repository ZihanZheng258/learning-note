**Parquet**（全称 **Apache Parquet**）是一种**开源的、面向列（Column-oriented）==**的数据存储文件格式，专为高效存储和查询大规模数据集而设计。==

它广泛用于 Apache Hadoop、Apache Spark、Azure Databricks、AWS S3 等大数据生态系统中的分析型工作负载。

### 核心特点：列式存储

Parquet 与传统的基于行（Row-based）的格式（如 CSV 或 JSON）最大的区别在于其存储方式：

| **特性**    | **Parquet (列式存储)**                                            | **CSV / JSON (行式存储)**                  |
| --------- | ------------------------------------------------------------- | -------------------------------------- |
| **数据组织**  | ==将一列的所有数据值连续存储在一起。==                                         | 将一行（一条记录）的所有字段连续存储在一起。                 |
| **查询性能**  | **极快。** 仅需读取查询涉及的列，跳过不相关的列，大大减少 I/O。                          | **慢。** 即使只需要一个字段，也必须读取整行数据，I/O 效率低下。   |
| **压缩效率**  | **极高。** 同一列数据类型相同，相似性高，可应用更优化的压缩和编码算法（如 Run-Length Encoding）。 | **较低。** 每行数据类型混杂，压缩效果一般。               |
| **写入/读取** | **读优于写。** 写入时需要将数据按列重新组织，较为复杂，但读取和分析性能极佳。                     | **写优于读。** 写入简单，但查询效率低。                 |
| **适用场景**  | **分析型查询 (OLAP)：** 例如 BI 报表、数据挖掘、大规模聚合运算。                      | **事务型处理 (OLTP) 或简单传输：** 例如消息队列、数据导入导出。 |

### Parquet 的主要优势

1. **查询速度快（性能提升）：**
    
    - 当执行分析查询时（例如 `SELECT user_age, user_salary FROM users WHERE user_id = '...'`），查询引擎只需读取磁盘上的 `user_age` 和 `user_salary` ==这两列的数据块，而忽略所有其他列（如姓名、地址等），极大地减少了数据 I/O，从而加快了查询速度。==
        
2. **存储空间节省（高压缩比）：**
    
    - ==列式存储允许 Parquet 对相似的数据类型和重复的值应用高效的压缩算法==，这通常可以节省 50% 或更多的存储空间。
        
3. **支持复杂数据类型：**
    
    - Parquet 不仅支持基本数据类型，还支持嵌套和重复结构（如数组、映射和结构体），使其能够高效地存储 JSON 或 NoSQL 数据库中的复杂层次结构数据。
        
4. **与计算框架集成：**
    
    - Parquet 格式是与 Apache Spark、Presto、Hive ==等主流大数据处理框架**深度集成**的默认数据源，这些框架可以利用 Parquet 的元数据和列式特性进行**谓词下推 (Predicate Pushdown)**==，即在读取数据时就进行过滤，进一步提高性能。
        

### Parquet 与 Avro 的对比

Parquet 和 Avro 都是流行的 Apache 数据格式，但它们的设计目标不同：

- **Parquet：** **面向列**，**读性能**优化，适用于**批量分析查询**。
    
- **Avro：** **面向行**，**写性能**优化，==适用于**流式消息**和强大的**模式演进**支持。==
