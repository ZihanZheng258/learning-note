“In-tree” 和 “Out-of-tree” 是 Kubernetes（K8s==）社区用来描述其**功能模块（特别是存储和云提供商集成）**的实现和发布模式的一对概念。==

### 核心区别：代码是否在 Kubernetes 核心代码仓库中

| **特性**   | **In-tree（树内）**                                | **Out-of-tree（树外）**                                             |
| -------- | ---------------------------------------------- | --------------------------------------------------------------- |
| **代码位置** | 代码包含在 **Kubernetes 核心代码库**中（例如：Kubelet 二进制文件）。 | 代码是**独立的项目**，与 K8s 核心代码库分离。                                     |
| **发布模式** | **与 K8s 核心同步发布**：更新和 Bug 修复必须等待 K8s 新版本发布。     | **独立发布**：供应商可以随时发布新版本，不依赖 K8s 的发布周期。                            |
| **集成方式** | 通过内部接口直接调用核心组件。                                | ==通过**标准接口**（如 CSI 或 CPI）以独立服务（通常是 Pod）的形式运行，并通过 **gRPC** 通信。== |
| **维护方**  | Kubernetes 社区和核心开发者。                           | 存储或云服务**供应商**自己维护。                                              |
| **目标**   | **历史模式**，Kubernetes 正在逐步**移除** In-tree 功能。     | **推荐模式**，所有新的集成都必须采用此模式。                                        |

---

### 一、In-tree (树内) 模式

In-tree 意味着集成代码是 **Kubernetes 整体的一部分**。

#### 优点

- **开箱即用：** 如果你的存储或云服务有一个 In-tree 插件，==你部署 Kubernetes 后，该功能就自动可用，无需安装额外组件。==
    

#### 缺点（为什么被淘汰）

1. **代码膨胀与耦合：** ==将大量供应商特定的代码塞入 K8s 核心代码，使得 K8s 二进制文件体积巨大，代码库复杂且难以维护。==
    
2. **安全性风险：** 任何供应商代码中的 Bug 或漏洞都可能直接影响 Kubelet 或其他核心组件的稳定性。
    
3. **开发受限：** 存储供应商无法快速迭代功能，必须遵循 K8s 严格的测试和发布流程（通常每三个月一次）。
    
4. **供应商不平等：** ==只有少数主流云厂商和存储类型最初获得了 In-tree 的地位。==
    

---

### 二、Out-of-tree (树外) 模式

Out-of-tree 意味着集成代码是作为一个**独立的服务（插件）**运行在 Kubernetes 集群之上的。

#### 优点

1. **解耦与稳定：** 存储/云提供商的逻辑与 K8s 核心组件完全分离。插件故障不会导致 Kubelet 崩溃。
    
2. **独立迭代：** 供应商可以根据自己的需求快速更新和发布驱动，用户也能及时获得新功能。
    
3. **更小、更精简的核心：** K8s 核心代码保持精简、通用和稳定。
    
4. **公平开放：** 任何新的存储或云提供商都可以基于标准接口（如 CSI）为 K8s 提供支持。
    

#### 缺点

- **部署步骤增加：** 用户部署完 K8s 集群后，还需要额外安装对应的 CSI 驱动（通常以 DaemonSet/Deployment 的形式）。
    

### 总结：K8s 的发展趋势

Kubernetes 社区正在进行一项名为 **“CSI 迁移”** 的长期工作，目标是**移除所有 In-tree 的存储驱动**（如 AWS EBS、Azure Disk、GCE PD 等的原生插件），并用相应的 **Out-of-tree CSI 驱动**取代它们。

因此，对于现代的 Kubernetes 集群和新的功能集成而言，**Out-of-tree** 是唯一的且推荐的模式。CSI 就是实现存储功能 Out-of-tree 的行业标准。
