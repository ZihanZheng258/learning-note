**PVC** 是 **PersistentVolumeClaim** 的缩写，中文常翻译为**持久卷申领**。

它是 Kubernetes（K8s）存储体系中的一个核心概念，==代表了**用户（应用开发者）**对存储资源的**请求**或**声明**。==

### 1. PVC 的定义和作用

在 Kubernetes 中，==存储体系通过两个主要资源对象来解耦应用和存储基础设施：==

| **资源对象** | **全称**                       | **作用定位**    | **关注点**                                      |
| -------- | ---------------------------- | ----------- | -------------------------------------------- |
| **PV**   | PersistentVolume（持久卷）        | **存储资源提供方** | 关注**集群如何提供存储**：存储的类型、容量、底层配置细节。==由集群管理员配置。== |
| **PVC**  | PersistentVolumeClaim（持久卷申领） | **存储资源使用方** | 关注**应用需要什么存储**：所需的容量、访问模式、性能等级。==由应用开发者配置。== |

**PVC 的核心作用**就是充当应用 Pod 与实际存储资源（PV）之间的**接口**或**代理**，将存储的实现细节对应用隐藏起来。

### 2. PVC 的主要内容（它声明了什么）

用户在创建 PVC 时，主要会声明以下几个需求：

|**字段**|**作用**|**示例值**|
|---|---|---|
|**`resources.requests.storage`**|**存储容量需求**：应用需要多大的存储空间。|`10Gi` (10 Gigabytes)|
|**`accessModes`**|**访问模式**：定义存储卷如何被 Pod 访问。|`ReadWriteOnce` (一次只能被一个节点读写)|
|**`storageClassName`**|**存储类别**：指定想要的存储质量等级（例如：高性能 SSD、低成本 HDD）。|`fast-ssd`|

### 3. PVC 的工作流程（生命周期）

PVC 的生命周期涉及与 PV 资源进行**绑定（Binding）**：

1. **用户创建 PVC：** ==应用开发者创建一个 PVC 对象，声明需要的容量和类型。==
    
2. **PV 匹配与绑定：** Kubernetes 的 Volume Controller 会持续监控 PVC。它会根据 PVC 的请求（容量、访问模式、StorageClass），在集群中查找一个**匹配且可用**的 PV。
    
    - **静态供给：** ==如果找到一个管理员提前创建好的 PV 与之匹配，则 PVC 和 PV 立即绑定（$\text{PVC} \leftrightarrow \text{PV}$）。==
        
    - **动态供给：** 如果找不到匹配的 PV，==且 PVC 指定了 StorageClass，CSI 存储插件会被调用，**自动创建**一个新的 PV 来满足 PVC 的需求，然后进行绑定。==
        
3. **Pod 使用 PVC：** 绑定完成后，用户可以在 Pod 的定义中将这个 PVC 作为 `volume` 类型引用。
    
4. **数据挂载：** Kubelet 负责将 PVC 绑定的底层 PV 对应的存储设备，==挂载到 Pod 内部的路径供容器使用。==
    
5. **资源回收：** 当用户不再需要存储时，删除 PVC。根据 PV 中定义的**回收策略（Reclaim Policy）**（如 `Retain` 保留、`Delete` 删除），存储资源会被保留或销毁。
    

总结来说，**PVC** 是 **Kubernetes 存储系统的用户视角**，它使开发者能够通过标准化的、声明式的 API 轻松获取和使用持久化存储，而无需关注后端存储的具体实现细节。
