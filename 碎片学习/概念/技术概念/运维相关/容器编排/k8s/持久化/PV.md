**PV** 是 **PersistentVolume** 的缩写，中文常翻译为**持久卷**。

它是 Kubernetes（K8s）==存储体系中的核心资源对象之一，代表了 Kubernetes 集群中的一块**实际的持久化存储资源**。==

### 1. PV 的定义和定位

==PV 是一个**集群级别的资源**，就像节点（Node）是集群资源一样==。它独立于 Pod 的生命周期而存在。

- **提供方视角：** PV 描述了集群中可用的**真实存储**。==它的创建和管理通常由**集群管理员**或**存储插件（CSI Driver）**负责。==
    
- **抽象细节：** PV 对象封装了底层存储的实现细节，包括存储类型（如 NFS、iSCSI、云盘、Ceph 等）、卷的大小和连接信息等。==应用开发者只需要通过 PVC 引用 PV，而不需要知道这些底层细节。==
    

### 2. PV 的主要内容（它定义了什么）

一个 PV 对象主要定义了关于存储资源的以下关键信息：

| **字段**                              | **作用**                                                | **示例值 / 描述**                                                                                                                                    |
| ----------------------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **`capacity`**                      | **存储容量**：该 PV 实际提供的存储空间大小。                            | `10Gi` (10 Gigabytes)                                                                                                                           |
| **`accessModes`**                   | **访问模式**：该 PV 支持哪些访问方式。                               | `ReadWriteOnce` (一次只能被一个节点读写)                                                                                                                   |
| **`persistentVolumeReclaimPolicy`** | **回收策略**：当其绑定的 PVC 被删除后，如何处理底层存储资源。                   | **1. `Retain`（保留）：** PV 对象被标记为释放，但底层数据和存储资源保留，需手动清理。 **2. `Delete`（删除）：** PV 对象和底层的存储资源（如云盘）都会被自动删除。 **3. `Recycle`（回收）：** 已弃用，通常用 `Delete` 取代。 |
| **`volumeMode`**                    | **卷模式**：定义 PV 是作为文件系统（`Filesystem`）还是裸块设备（`Block`）使用。 | `Filesystem`                                                                                                                                    |
| **`storageClassName`**              | **存储类别**：将 PV 与特定的 StorageClass 关联起来，用于动态供给。          | `fast-ssd`                                                                                                                                      |
| **`spec.xxx`**                      | **存储后端细节**：指定底层存储的类型和连接参数（如 NFS 服务器地址、云盘 ID 等）。       | `nfs: {server: "10.0.0.1", path: "/exports"}`                                                                                                   |

### 3. PV 与 PVC 的关系总结

PV 和 PVC 共同构成了 Kubernetes 的持久化存储抽象层：

|**特点**|**PV (PersistentVolume)**|**PVC (PersistentVolumeClaim)**|
|---|---|---|
|**角色**|存储资源（供应方）|存储请求（使用方）|
|**创建者**|集群管理员或 CSI Provisioner（存储插件）|应用开发者或用户|
|**作用范围**|**集群级别**（不属于任何命名空间）|**命名空间级别**（必须在 Pod 所在的命名空间）|
|**关系**|**一对一绑定**：一个 PV 在任何时候只能绑定一个 PVC。|**一对一绑定**：一个 PVC 只能绑定一个 PV。|

通过 PV 和 PVC 的解耦机制，应用开发者只关心“我需要 10GB 快速存储”（PVC），==而集群管理员只关心“如何提供 10GB 快速存储”（PV），实现了两者关注点的分离。==
