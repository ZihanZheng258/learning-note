分片上传（Chunked Upload）和分片下载（Chunked Download）是优化大文件传输效率和稳定性的两种核心技术。==它们的核心思想都是将一个大文件拆分成多个小的、独立的部分（**分片/块**）进行传输。==

## 1. 分片上传（Chunked Upload）

**分片上传**是指在客户端（浏览器或应用程序）将一个完整的大文件分割成若干个较小的文件块，然后将这些文件块**并行或串行**地上传到服务器。

### 核心原理

1. **客户端分割：** 文件在上传前被切分成固定大小的数据块（例如 1MB 到 10MB）。
    
2. **独立上传：** 每个数据块作为一个独立的 HTTP 请求发送到服务器。
    
3. **服务器合并：** 服务器接收到所有分片后，会根据分片信息（如索引、总数）进行排序和校验，最终将它们**合并**成原始的完整文件。
    
4. **校验：** 通常每个分片都会带有**哈希值（Hash）**，用于校验数据在传输过程中是否损坏。
    

### 主要效果和优点

|效果/优点|描述|
|---|---|
|**断点续传**|如果上传过程中网络中断，只需要重新上传失败或未上传的分片，而不是从头开始，大大提高了大文件上传的成功率。|
|**提高速度**|多个分片可以同时（并行）上传，充分利用带宽，加快整体上传速度。|
|**减少超时**|避免单个 HTTP 请求因传输时间过长而导致超时失败。|
|**秒传**|服务器可以检查已上传分片的哈希值。如果发现该文件（或部分分片）以前被上传过，可以直接跳过上传步骤，实现“秒传”。|

## 2. 分片下载（Chunked Download）

**分片下载**是指客户端（通常通过 HTTP 协议）向服务器请求一个大文件的不同部分，==然后将这些部分**并行或串行**地下载到本地。==

### 核心原理

分片下载通常依赖于 HTTP/1.1 协议中的两个机制：

#### A. **基于 Range 的分片（最常见）**

- **客户端请求：** 客户端在 HTTP 请求头中添加 **`Range`** 字段，指定要下载的文件字节范围，例如 `Range: bytes=0-1023`（请求前 1024 字节）。
    
- **服务器响应：** 服务器返回 **`206 Partial Content`** 状态码，并在响应体中只包含请求的字节范围数据。
    
- **并行下载：** 客户端可以发起多个带有不同 `Range` 的请求，并行下载文件的不同部分。
    

#### B. **Transfer-Encoding: chunked（与分片下载概念不同但相关）**

- 这是服务器向客户端发送数据的一种方式，**它表示响应体数据是分块传输的**，但这种“分块”主要用于服务器不知道响应体最终大小的情况，**与客户端主动请求文件部分不同**。不过，现代浏览器和客户端都会自动处理这种编码。
    

### 主要效果和优点

|效果/优点|描述|
|---|---|
|**断点续传**|如果下载中断，客户端可以计算已下载的字节数，并用 `Range` 头部从中断的地方继续请求下载。|
|**提高速度**|允许多线程/多连接并行下载文件的不同部分，显著提高下载效率（如迅雷等下载工具）。|
|**流式播放**|对于视频、音频等流媒体文件，客户端可以只下载需要播放的那一部分，实现**边下边播**，无需等待整个文件下载完成。|
|**节省资源**|允许客户端仅下载文件中的特定部分（如 PDF 的某一页），节省用户带宽。|
