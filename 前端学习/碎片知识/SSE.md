## SSE（Server-Sent Events）的本质是下载

从 HTTP 协议和数据流的角度来看，**SSE 确实是一种特殊的、单向的下载技术**。

SSE 的全称是 ==**服务器发送事件**，它允许服务器在建立连接后，主动向客户端（浏览器）推送数据。==

### 1. 技术上的支撑

SSE 工作的核心在于 HTTP 协议和特殊的 `Content-Type`：

- **HTTP 协议：** SSE 是基于标准的 **HTTP/1.1 协议**建立的。
    
- **连接持久化：** 客户端发起一次普通的 GET 请求，但服务器**不关闭连接**，而是保持连接处于打开状态。
    
- **特殊的 MIME 类型：** 服务器在响应头中设置 ==`Content-Type: text/event-stream`。这个头部告诉浏览器，接下来的数据将是一个持续的事件流，而不是一次性的完整文件。==
    

### 2. 与传统下载的类比

你可以将 SSE 理解为一种**无限期的、流式的文件下载**：

| 特性         | 传统文件下载              | SSE (Server-Sent Events)                            |
| ---------- | ------------------- | --------------------------------------------------- |
| **请求方式**   | 客户端发起 GET 请求。       | 客户端发起 GET 请求。                                       |
| **数据流向**   | **单向**：数据从服务器流向客户端。 | **单向**：数据从服务器流向客户端。                                 |
| **连接生命周期** | 下载完成后连接立即**关闭**。    | ==连接被有意地保持**打开**状态。==                               |
| **数据格式**   | 二进制文件、JSON 文本等。     | 必须是遵循特定格式的 **事件流**（==带有 `data:`、`event:` 等前缀的文本）==。 |

## SSE 与 WebSocket 的区别

理解 SSE 的本质，有助于区分它与另一个流行的实时通信技术 **WebSocket**：

| 特性       | SSE (Server-Sent Events)     | WebSocket                      |
| -------- | ---------------------------- | ------------------------------ |
| **方向性**  | **单向**（服务器 → 客户端）            | **双向全双工**（服务器 ↔ 客户端）           |
| **协议**   | **基于 HTTP**                  | **基于独立的 WS 协议**（但通过 HTTP 握手升级） |
| **数据格式** | 纯文本事件流 (`text/event-stream`) | 帧 (Frames)，可传输文本或二进制数据         |
| **适用场景** | 实时新闻、股票报价、进度条等纯推送场景。         | 聊天室、多人游戏、需要双向通信的场景。            |
