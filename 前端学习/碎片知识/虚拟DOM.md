**虚拟 DOM** (Virtual DOM，简称 VDOM) 是一个核心概念，它并非是浏览器规范的一部分，==而是由像 **React、Vue、Svelte** 这样的现代前端框架发明和实现的一种**编程概念和技术**。==

它的核心目的是为了**提高应用性能**、**简化 DOM 操作**，并使前端代码具有**跨平台能力**。

## 虚拟 DOM 的定义

虚拟 DOM 是一个**轻量级的、内存中的 JavaScript 对象树**（或树状结构），它忠实地映射了浏览器实际 DOM 树的结构。

你可以把它想象成是真实 DOM 的一个“蓝图”或“快照”。它包含了你在页面上看到的所有元素、它们的属性和内容，但它**不具备真实 DOM 的所有复杂特性**（比如布局计算、实际渲染等）

## 为什么需要虚拟 DOM？

虚拟 DOM 存在的根本原因是为了解决**直接操作真实 DOM 带来的性能问题**。

### 真实 DOM 的性能瓶颈

- **开销大：** 真实 DOM 操作非常昂贵且慢。每次对 DOM 的修改，都可能触发浏览器的**重排**（Reflow，重新计算布局）和**重绘**（Repaint，重新绘制像素），这是非常耗时的操作。
    
- **效率低下：** 在传统开发中，即使用户界面只需要修改一小部分，开发者往往会不经意间执行大量低效的 DOM 操作。
    

### 虚拟 DOM 的解决方案

==VDOM 通过引入一个**缓冲层**，将变化集中处理，从而最大限度地减少对真实 DOM 的直接操作次数。==

## 虚拟 DOM 的工作流程（“三步走”）

VDOM 的整个工作流程可以概括为以下三个步骤：

### 1. 渲染 VDOM (Render)

当应用的状态发生变化时，框架会**重新渲染整个组件树**，并创建一个**新的虚拟 DOM 树**。

- **旧 VDOM 树：** 上一次状态更新后生成的 VDOM 快照。
    
- **新 VDOM 树：** 当前状态更新后生成的 VDOM 快照。
    

### 2. 对比差异 (Diffing)

这是 VDOM 最关键的步骤。==框架会高效地将**新 VDOM 树**与**旧 VDOM 树**进行**深度比较**==，找出两者之间的所有变化（哪些元素属性改变了？哪个节点被删除了？哪个子列表顺序变了？）。

- 这个过程称为 **Diff 算法**。它不会遍历整个树的所有可能性（这太慢了），而是基于一些优化规则（例如同层比较、基于 key 列表比较）进行快速计算。
    
- Diff 算法的输出是一系列==**最小化的 DOM 操作指令**（比如：“将 div 的 class 属性从 A 改为 B”）。==
    

### 3. 补丁与同步 (Patching)

框架根据 Diff 阶段生成的最小化指令集合，==对**真实 DOM** 进行**批量、高效**的修改。==

- 框架将所有必要的 DOM 操作**集中一次性**完成。
    
- 通过这种方式，它避免了多次不必要的重排和重绘，大大提高了性能。
    

---

## VDOM 的延伸优势

除了性能之外，虚拟 DOM 还带来了其他强大的能力：

- **服务器端渲染（SSR）：** 由于 VDOM 只是 JavaScript 对象，==它可以在没有浏览器环境的 **Node.js 服务器**上生成 HTML 字符串，实现 SSR==。
    
- **跨平台开发：** VDOM 可以被“渲染”到浏览器 DOM 之外的其他环境，==比如 React Native 可以将 VDOM 映射到**原生移动应用组件**上。==
    

简而言之，**虚拟 DOM ==是真实 DOM 的 JavaScript 抽象表示==，它通过在内存中进行高效的差异对比，将对真实 DOM 的操作最小化和批量化，从而提升了现代前端应用的性能和开发体验。**
